# Registration in the existing Node server

The module does not own `app.mjs`. Its owner should register the following without weakening
existing body, origin, session, or production-write gates.

```js
import { createGarProvider } from './location/provider.mjs';
import { createLocationService, LOCATION_METHODS, locationDetailId,
  locationSuggestions } from './location/service.mjs';

// After the sessions / quotes tables exist. A missing index does not block startup.
const locationProvider = createGarProvider({
  databasePath: locationDatabasePath ?? resolve(HERE, 'location/data/gar.sqlite'), fail, now,
});
const locations = createLocationService({ db, provider: locationProvider, fail, now });

// Extend staticMethods with ...LOCATION_METHODS.
// Permit query parameters only on existing catalog and /api/v1/locations/suggest.
const settlementId = locationDetailId(path);
// Include settlementId ? ['GET'] in dynamic method matching.

// BEFORE auth, and only after the method/origin checks:
if (path === '/api/v1/locations/suggest') {
  send(200, { data: locationSuggestions(locationProvider, url.searchParams, fail) }); return;
}
if (settlementId) {
  const item = locationProvider.getById(settlementId);
  if (!item) fail(404, 'SETTLEMENT_NOT_FOUND', 'Населённый пункт не найден в актуальном справочнике.');
  send(200, { data: item }); return;
}

// The old path.startsWith('/api/v1/') dispatch MUST be narrowed to the three
// public routes it actually serves; otherwise it treats /location as catalog.

// AFTER POST readBody and fresh sessionFor (including existing consumer/debug policy):
if (path === '/api/v1/location') {
  send(200, { data: request.method === 'GET' ? locations.get(session) : locations.select(session, body) }); return;
}
if (path === '/api/v1/cart/revalidate-location') {
  locations.revalidate(session, body); return; // currently throws a specific unavailable error
}

// During server close:
locationProvider.close();
```

New sessions use empty legacy city, so an old autogenerated default is not introduced again.
Old exact-unique names may be exposed as `selectionSource: legacy-exact`, version 0, without
writing during GET. Ambiguous names return settlement null. An explicit POST persists the
official ID and version. `POST /api/actions` type=city must fail with
`SETTLEMENT_SELECTION_REQUIRED`; do not silently accept free text through the legacy route.

An explicit location selection revokes unconsumed old quotes for both contexts. The existing
consumer checkout/write gate remains closed: this module does not authorize making new
snapshot quotes/orders, even after it successfully saves a location. Geography and real commerce
readiness are separate. `state.city` is only the official fullName compatibility label.
