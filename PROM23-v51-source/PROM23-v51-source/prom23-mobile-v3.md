# Итерация 3 — точный перенос сайта

Запрос владельца: идентичная каталогу сайта структура разделов; логотип; доставка; Яндекс Пэй/Сплит и бонусы; B2B-конверсия и собственное производство; интеграции Bitrix24 и 1С. Функциональный источник — только сайт, не конкуренты.

1. Восстановить полное дерево реальных разделов из кода и публичного меню staging, сохранить порядок/названия/ссылки и связать товары по действительным разделам. Не выдавать выборку товаров за полный ассортимент.
2. Найти и перенести собственный логотип и контент доставки, оплаты, B2B, производства. Проверить условия Сплита/бонусов в исходниках и актуальной официальной документации Яндекса; суммы не подменять выдуманным графиком платежей/кэшбэком.
3. Разобрать имеющиеся обмены Bitrix24/1С и точки создания заказа/оплаты. Сохранить Bitrix источником данных; разработать переносимый серверный адаптер к существующей логике, не писать повторные лиды напрямую из приложения и не использовать webhook сайта БПЛА для другого бизнес-процесса.
4. Заменить упрощённые мобильные разделы точной навигацией; добавить недостающие страницы/блоки и действия, используя исходники как спецификацию. Поля, бизнес-правила и ограничения брать с сайта.
5. Проверить data contracts, переходы, мобильные экраны, интеграционные конфигурации, сборки JS/native project. Зависимые от отсутствующего контура функции не называть настроенными до реального теста обмена.
6. Развернуть обновлённую сборку только в prom23-mobile-preview на 18087. Не изменять файлы/настройки/процессы zavod-antibpla.ru. Контрольные суммы и состояния служб проверить до/после.

План создан до возобновления специалистов по app-builder. Существующие ограничения доступа и запрет реальных платежей/неподтверждённой передачи ПД сохраняются. Работа с оригинальным PHP — чтение/адаптация, не исполнение неизвестного архива в production.

Дополнение из голосового разговора 11.09: системные push + история уведомлений с переходами; независимые настройки сервисных и рекламных сообщений; адреса/маршрут/контакты/позвонить/менеджер; измеримые performance-критерии и реальные устройства до заявления о готовности. Сохраняем source-поля email/SMS, push добавляется по прямому запросу владельца. Реальные рассылки не отправляем.
