## B2C: доказательство ошибки и нужный инвариант

`getRegionData()` читает выбранное cookie в строке 430. В строках 446–450 список исключений остаётся пустым, кроме тестового SERVER_NAME, где добавлены `kg/am/az/kz/by`. В строке 468 вычисляется `physical && !in_array(cityData.domain, domains)`. Строки 474–481 при истинном условии присваивают DEFAULT_CITY; строка 491 уже называет городом это заменённое значение. Поэтому на обычном домене physical теряет влияние своего выбора на коммерческий регион. При этом cookie и надпись шапки могут продолжать содержать ранее выбранное место. Для legal действует другой путь.

Новый инвариант: **подтверждённый Settlement сохраняется одинаково для B2C и B2B**. Коммерческие права, цена, допустимая доставка и оплата вычисляются отдельно по пользователю/организации и месту. Ни переключение режима, ни вход после гостевого выбора не подставляет Краснодар незаметно. Исходный архив не исправлялся.

## Профиль и адрес доставки

`local/ajax/lk/info/edit/forms/change-city.php:21` — свободное текстовое поле. `change-user-data.php:17` проверяет авторизацию и Bitrix sessid; строка 44 принимает city. `local/class/Models/User.php:175` сохраняет его в PERSONAL_CITY. Здесь нет официального ID и доказанной синхронизации с cookie region: это самостоятельная legacy-строка.

`local/ajax/order/resolve-location.php:18–38` отправляет полный свободный адрес поставщику подсказок с серверным ключом. Этот ключ не использовался. Из первого ответа берётся city, иначе settlement, иначе region (45). Затем LocationTable ищется **по имени, только TYPE.CODE=CITY, limit=1** (58–66). Район, регион и официальный ID игнорируются. Сёла/хутора могут не найтись; одноимённые города могут связаться с чужой локацией. Нельзя применять этот алгоритм в новом API.

`local/class/Models/AddressDeliveryUsers.php:24–49` сначала распознаёт г/гор/город/пгт/рп/дп/кп в строке, затем использует эвристику частей адреса. `resolveLocationFromAddress:57–105` повторяет name + CITY + first result и берёт ZIP из ExternalTable либо шесть цифр из текста. Создание (242–298) и изменение (304–350) сохраняют результат вместе с FULL_ADDRESS; официальный Settlement/улица/дом раздельно не хранятся.

KEEP: чтение/изменение/удаление адресов ограничены USER_ID + активным ORGANIZATION_ID (`111–148`, `154–193`, `304–350`, `355–430`). Схема `Models/EO/AddressDeliveryUsers.php:15–44`: ID, USER_ID, ORGANIZATION_ID, FULL_ADDRESS, LOCATION_CODE, ZIP, CREATED_AT, IS_MAIN. Новый адаптер обязан сохранить это разграничение. Одного знания address ID недостаточно.

В `local/templates/main/components/bitrix/sale.order.ajax/main/result_modifier.php:154–172` первоначальный CITY_CODE определяется по **названию склада**, TYPE=CITY и первой записи. Основной сохранённый адрес приоритетнее этого fallback (192–196). Не переносить фиктивные PICKUP_ADDRESSES из 126–129 в новый список складов.

## Корзина, цена и смена склада

`local/ajax/order/change-region.php:8–14` намеренно не меняет город шапки: это операция выбора склада. При reset берутся текущие price codes (17–21). ID выбранного коммерческого региона разрешается по активной записи (39–55), из которой берутся STORE/PRICE_CODE. Для чужого склада используются юридические цены региона и FREE_PAYMENT_SYSTEM (68–85). Это не означает, что населённый пункт покупателя стал городом склада.

`local/class/Models/BasketUsers.php:421–536` разрешает `_SALE` или первый тип цены через GroupTable, обновляет **CATALOG_GROUP_XML_ID** в свойствах корзины, снимает CUSTOM_PRICE, сохраняет, делает provider refresh, снова сохраняет. Если цены региона нет, товар остаётся с прежним типом цены (490–499). Следовательно, одна цифра старой цены не доказывает возможность покупки в новом регионе.

`change-region.php:90–141` формирует unavailable только для чужого склада: нет цены либо существующая запись AMOUNT≤0. **Отсутствующая запись остатка не равна доказанному наличию**. Мобильный контракт обязан передавать `unknown`, а не stock>0. В result_modifier:110–117 есть различающиеся B2C/B2B ограничения доставок; их нельзя восстановить по общему тексту страницы.

Для честного revalidation нужны работающий CatalogProvider, цены/складские записи, региональные свойства, корзина FUser и права организации. Их runtime-данных в архиве нет. Новая операция до подключения Bitrix возвращает недоступность; сохраняет позиции, не делает «успешный пересчёт» по снимку каталога, не создаёт заказ.

## Состояние приложения до MASTER4

`server/app.mjs:28` хранит `city: 'Краснодар'` как строку sandbox-сессии. Legacy action city принимает текст; это не справочник населённых пунктов. `server/public-v1.mjs:6` содержит список публичных филиалов как допустимые city для snapshot каталога; он не является географией РФ. `/api/v1/catalog` явно имеет regionalPricing=false и checkoutEligible=false. **Нельзя переименовать эти филиалы в официальный реестр или выдумать mapping по названию.**

## Официальный источник и проверенные ограничения

- [ФНС: назначение ФИАС/ГАР](https://www.nalog.gov.ru/rn77/service/fias/): государственная адресная информация. [Открытые данные ФНС](https://www.nalog.gov.ru/opendata/7707329152-fias/) дают XML и схему, а не список филиалов магазина.
- Публичный GET [GetLastDownloadFileInfo](https://fias.nalog.ru/WebServices/Public/GetLastDownloadFileInfo), выполненный 11.09.2026, вернул VersionId=20260911, GarXMLFullURL на `https://fias-file.nalog.ru/downloads/2026.09.11/gar_xml.zip`.
- Range GET подтвердил ZIP64 размером **57 539 281 878 байт**. Полная база не загружалась. Центральный каталог 246 074 байта содержит 96 региональных AS_ADDR_OBJ (суммарно 139 364 715 сжатых байт) и AS_ADM_HIERARCHY (~2,64 ГБ сжатых данных). Это технические размеры конкретной версии, не обещание неизменности схемы.
- Требуются актуальные/активные адресные объекты, официальные типы и административная иерархия. UUID надо читать из OBJECTGUID, GAR object ID — из OBJECTID; не генерировать и не брать ID коммерческого региона. Сопоставление с Bitrix LOCATION_CODE — отдельная подтверждаемая таблица.
- Схема/состав локальной выборки и реальная полнота будут зафиксированы после импорта. Пока нельзя объявить поиск по всей РФ выполненным. Отсутствие результата вне покрытия не означает, что населённого пункта нет.

## Итог аудита

KEEP: региональные свойства Bitrix, разделение города шапки и склада самовывоза, BasketUsers/CatalogProvider, USER_ID+ORGANIZATION_ID для адресов. REFACTOR: HTML→JSON, cookie/string→официальный ID, CITY-only/name-first→точный mapping. BUILD: независимый Settlement provider, версия выбора, поиск с опечатками, миграция неоднозначных строк через подтверждение. RISK: B2C DEFAULT_CITY, отсутствующие коммерческие runtime-данные, недоказанные остатки и SLA.
