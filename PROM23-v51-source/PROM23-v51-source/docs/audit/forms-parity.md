# Forms parity — UI, source contract and runtime gates

**Последнее уточнение пользователя: B2C и B2B равнозначно важны.** Consumer default не означает снижение B2B-приоритета. Личная покупка доступна без организации; закупка с файлом и корпоративные возможности заметны рядом, с самостоятельным сценарием.

Дата: 11.09.2026. MASTER4 baseline + MASTER5 verification. Аудит исходников и публичных страниц с последующими ограниченными исправлениями mobile registry (см. раздел ниже); PHP/Bitrix, реальные формы, OTP, CRM и платежи не выполнялись. Реальные операции проверят программисты после подключения; staging и учётные записи не являются условием этой итерации. Статус BACKEND GAP означает неподключённый контракт, а не запрос доступа пользователю. Секретные значения не включены.

## Конкретные динамические и validation gaps

- **advice / OrangeAsk**: вся структура вопросов, numeric answer IDs, SID/type/REQUIRED принадлежат CForm. Нельзя заменить придуманными name/email/message.
- **document-request / REQUEST_DOCUMENT**: DOC_TYPE, PERIOD_FROM, PERIOD_TO, COMMENT — SIDs, не доказанные numeric input names. Required и допустимые document types неизвестны без snapshot runtime.
- **callback, one-click, rent, leasing, found-cheaper, tour**: поля отражены по source/live snapshot, но handlers снова читают CForm::GetDataByID и COMMENTS validation. Static template не заменяет effective form schema. Аренда на публичной форме не имеет phone — не добавлять по аналогии. Leasing намеренно использует общий request-a-call handler с веткой addLeasing.
- **checkout**: order property IDs, person type, address required, delivery/payment options, pickup/date/time и скидки authoritative на сервере. `ORDER_*` mobile labels — DTO placeholders, не настоящие numeric property IDs. Нельзя копировать test-email/static intervals из source template.
- **organization-add/switch/EDO**: store-region enum, собственные компании и операторы ЭДО из backend; membership нельзя вывести из mobile context string.
- **organization-bank**: данные read-only из lookup, нет независимого edit handler. **consignee**: unnamed controls, связанная запись не подтверждена.
- **return**: completed owned order, allowed item IDs, REASONS enum; comment/reasons/photos повторяются для каждого товара. Текущая dynamic context пустая, поэтому реальный возврат невозможен. Нельзя упрощать до одной причины.
- **appeal**: HTML300/1500 characters и handler strlen500/2000 bytes расходятся для кириллицы. Установить единый измеряемый лимит backend/client; не заявлять точный MATCH текущей базовой валидации.
- **upload**: mobile DocumentPicker проверяет расширение/число/размер и хранит выбранные assets в состоянии. Private upload IDs, MIME signature, malware scan, durable upload/retry и передача CRM отсутствуют. Значения файла не отправлялись. `supplier` CFile::CheckFile(...,0,false,false) не является готовой общей allowlist-политикой для procurement.
- **mapping**: sourceName/sourceValue описывают исходные поля; serializeFields возвращает mobile DTO names, не автоматически PHP `votes[]`/numeric names. BFF должен явно преобразовать контекст/поля и не посылать DTO в HTML endpoint.
- **success/retry/consent**: loading/error/state UI есть; durable idempotency, CRM reference и журнал версии согласия ещё должны быть реализованы. Кнопочный saving guard не равен серверной защите повторной отправки. В endpoint request нет consent document version/hash — добавить при подключении.
- **account deletion**: исходный флаг UF_DELETE_ACCOUNT_BY_USER не означает физическое удаление. Отдельная очередь retention/anonymization/completion — задача lifecycle; текущий текст потери всех данных пересмотреть.
- **payment-card**: PAN/expiry/CVV source path намеренно не портирован. 🟢 MOBILE IMPROVEMENT по capture boundary не делает неподключённую provider session рабочей.

## Attachment gap исходного аудита → исправление mobile registry

До исправления `appeal-order` и повторяемые items в `return` были ограничены mobile photo() до JPG/JPEG/PNG, хотя source handlers поддерживают видео: `local/ajax/lk/appeals/appeals-order-form-action.php:130`, `local/ajax/lk/returns-products/action-returns-product.php:302` проверяют `video/*` и длительность до1мин, размер20MB. Расширения и лимиты mobile registry теперь восстановлены только для этих двух сценариев. Сохраняется **🚧 BACKEND GAP** проверки фактического содержимого и длительности на upload service; расширение не считать безопасной сигнатурой.

Source MIME allowlist уточнена: `local/php_interface/functions.php:266` — image/jpeg,image/jpg,image/png,image/gif,image/webp; video/mp4,video/avi,video/mov,video/wmv,video/flv,video/webm. Воспроизводить разрешённый набор через безопасный upload service, не доверять MIME из multipart.

## Ограниченные исправления P0 · mobile registry и лист ожидания

`siteForms.ts`: checkout сохраняет необязательные `pod`, `etag`, `office`, `comment` отдельно от `ORDER_ADDRESS`, для B2C и B2B. В `local/ajax/order/popup-curier.php` required есть только у `address`. Исходный `script.js:updateAddress` соединяет непустые значения в ORDER_ADDRESS (скрытое `ORDER_PROP_{ADDRESS}`), а location ищет по базовому `address`. Адаптер должен выполнить это отображение после проверки способа получения и населённого пункта; произвольный текст не становится location ID. Профильные address-create/edit оставлены с единственным `full_address`: их другой popup не содержит этих четырёх полей. `FormScreen.tsx` в этой подзадаче не изменялся.

`appeal-order`: точное multipart имя `photos[]`, необязательное, максимум 10 файлов. `return`: `item-{index}-photos[]`, максимум 10 **на возвращаемый товар**, поле необязательное. Mobile DTO хранит массив `photos[]` внутри строки выбранного разрешённого `items`; BFF преобразует ключ строки в проверенный сервером item index, не принимает подставленный индекс. Другие photo() поля и обычное обращение `appeal` не получили видео.

Для обоих сценариев `supportMedia` задаёт расширения из фактической allowlist, 20×1024×1024 байт на файл и metadata `serverFileValidation`: допустимые MIME, maxVideoDurationSeconds=60, rejectUnreadableVideo=true. UI явно сообщает, что содержимое и длительность должны проверяться сервером при отправке. DocumentPicker проверяет лишь имя, количество и сообщённый размер; длительность клиентом **не подтверждена**, выбранный asset не равен принятой загрузке.

Контракт загрузки: определить тип по реальным байтам, нормализовать распознанные MIME aliases (например, QuickTime для MOV), сверить allowlist, размер и квоту, приватно сохранить файл, проверить видео. При ошибке анализа, пустой/нечисловой/неположительной длительности — отказ; допустимо только 0<duration≤60. Исходный helper использует multipart MIME и `floatval` вывода ffprobe, поэтому его нельзя считать достаточной безопасной реализацией. Перед CRM нужны отдельный upload ID, проверка принадлежности заказа/товара, идемпотентность и надёжная передача; они не реализованы этим изменением registry.

`/workspace/waiting-list` добавлен в существующий `WorkspaceScreen`: заголовок, unavailable состояние, каталог, вход, контакты, возврат штатной Header. `loadSiteWorkspace('waiting-list', context)` возвращает `{records: [], available: false}` и не выполняет сеть. Подписки и успешное включение уведомлений не создаются. Ссылка из кабинета принадлежит основной UI-итерации.

Source: `local/class/Models/WaitingList.php:getItems` фильтрует активные товары, а для авторизованного пользователя — UF_USER_ID+UF_ORGANIZATION_ID; модель также имеет guest-session fallback. Но публичный `local/ajax/catalog/action-add-to-waitlist.php` требует авторизацию+sessid. Это различие сохранено: существующий `product-notify` остаётся authenticated-user, поддержка гостевого toggle не выдумана. Публичный лог исходника с user/product ID в мобильную интеграцию не переносится.

Проверено: `npm run typecheck` PASS; `node --import tsx --test tests/forms.test.ts` **8/8 PASS**. Новые проверки подтверждают сохранение адресных деталей, изоляцию медиа по выбранному товару, отсутствие расширения видео на другие формы и пустой unavailable WaitingList без fetch в обоих контекстах. Это source/model verification, не реальная загрузка видео или успешный возврат.
