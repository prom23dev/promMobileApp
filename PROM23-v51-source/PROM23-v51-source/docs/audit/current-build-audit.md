## Факты, которые меняют диагноз

1. **B2C уже есть и является состоянием нового гостя.** В новом isolated Chrome context главная показывает «Для себя», кабинет — «Ваши покупки под контролем», заказы, личные данные, адреса и способы оплаты. Организация для личной корзины не требуется.
2. **Корпоративный экран воспроизводится сохранённым выбором.** Переключение «Для компании» → reload оставляет company context; в товаре вместо личного Сплита/Плюса появляется «Счёт · НДС · ЭДО». Это объясняет соответствующий скриншот, но не доказывает, что именно так возникло состояние пользовательского браузера: чужой профиль не исследовался. Вернув «Для себя», получаем consumer UI. В коде это `state.context`, `organization-demo` и `AccountBenefits`/`PaymentBenefit`.
3. **География сломана как доменная модель.** «Краснадарррр123» можно подтвердить и увидеть в шапке. Сохраняется строка, не settlement/FIAS; server action `city` меняет строку без региональной переоценки корзины. Замена autocomplete без изменения контракта проблему не решит.
4. **Рабочая локальная сессия не равна аккаунту магазина.** Catalog API baseline отдаёт 28 товаров, `mode:local-sandbox`, снимок `2026-09-11T06:12:03Z`. `loadSiteWorkspace` возвращает empty/unavailable, `loadSiteFormContext` — `{}`, `submitSiteForm` — ошибку без отправки. UI не выдумывает успешный заказ, но полноценной commerce integration сейчас нет.
5. **Закупка и Quick Order смешаны.** Текущий вход ведёт в список артикулов, не в отдельную ProcurementRequest с контактами, населённым пунктом и файлом потребности. Вторичный Quick Order исправно существует и должен сохраниться.

Доказательства: [runtime](current-build-runtime.json), [дополнительные сценарии](current-build-supplement.json), [инвентарь маршрутов](mobile-screen-inventory.md), [регрессия](../testing/regression-matrix.md). Обход проверяет рендер каждого именованного варианта; это не заявление о выполненной отправке всех форм.

Итог обхода baseline: **184/184 URL variants открылись**, 0 ошибок JavaScript, 0 горизонтального переполнения документа на 390×844, 0 попыток запрещённых записей. Первоначальная попытка checkout использовала устаревшую подпись кнопки; повтор с фактической «Перейти к оформлению» прошёл, что отдельно зафиксировано в supplement. Список результатов не подменяет приёмку динамических данных и всех ролей.

## Границы доказательства

Новый browser context, никаких личных учётных записей или credentials. Разрешены только sessions/actions этого изолированного preview; остальные POST/PUT/PATCH/DELETE и tel/mailto/sms блокируются. Ни реальные формы, ни звонки, ни заказы не отправлялись. Сохранён только UI-текст/каталожные данные; session tokens не записывались в отчёт. Native build, native permissions, VoiceOver/TalkBack и реальная commerce acceptance в этом проходе не выполнялись. Отсутствие подключённой службы — gap для реализации/передачи программистам, а не запрос владельцу о новых доступах.
