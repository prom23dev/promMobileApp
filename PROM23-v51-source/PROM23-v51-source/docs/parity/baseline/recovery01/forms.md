## Общие конкретные потери реализации

1. `api/site.ts:23–30`: context всегда{}, submit всегда throw. Это **MISSING callable integration**, не BLOCKED_BY_EXTERNAL_ACCESS. `procurement.ts` повторяет этот pattern; `client.ts` — общий HTTPS transport без конкретного runtime wiring.
2. `forms/formModel.ts:37` сериализует mobile field name, игнорирует sourceName/sourceValue: vote-quality/value/delivery не становятся votes[], theme не становится theme_id, booleans не становятся Y/on, repeated return fields не становятся source item-index controls. Mapping должен выполняться в серверном operation wrapper с field allowlist.
3. `forms/formModel.ts:24` не проверяет source password strength, numeric1..99, byte-length лимиты и input masks. TextInput maxLength не серверная validation. Примеры source: `functions.php:289–304`, `action-buy-one-click.php:93–100`, `appeals-text-action.php` strlen2000.
4. `FormScreen.tsx:42–49`: context loader не имеет загрузочного state с retry/allowedActions; readonly profile/organization values пусты. Source uses existing authenticated values, CForm/HL options и exact target eligibility.
5. `FormScreen.tsx:73–103`: единственный accepted+reference success контракт не покрывает challenge-issued/next step/authenticated/updated/redirect/payment-pending; nextFormId не переносит challenge. source STATUS/ERRORS/TIMER/CODE_PUBLIC/OPEN_POPUP_AJAX/REDIRECT нужно нормализовать, произвольный source URL не исполнять.
6. FilePicker локально выбирает файлы; настоящий bounded upload, sniffing/AV/duration/ownership/expiry и cleanup отсутствуют. `serializeFields` сейчас содержит device URI, не upload token. Upload mapping различен: review root photos, order-review media, supplier attachment, support photos, return indexed photos, organization3files.
7. Source CForm request may save locally and ignore failed CRM/mail result (например suppliers-form-action.php125–181). В адаптере разделять acceptedLocal/pendingIntegration/delivered и сохранять idempotency/outbox; никогда не говорить CRM success по одному CForm ID.
8. Реестр согласий сохраняет видимые source names, но receipt с документом/версией/моментом/действием ещё не реализован. Read-only legal links не равны consent. Исходные checked/default значения не трактовать как согласие нового пользователя.
9. У account-delete и organization-delete есть source model/query action, хотя sourceAction в registry отсутствует. Нужен POST wrapper, owner-check и сессионная revocation. Source User soft-delete не обещает физическое стирание заказов/бухгалтерии.
10. Procurement: UI/validation есть, но source business-advice не принимает Excel/набор файлов как готовый procurement contract. Реализовать явный operation с attachments→approved CRM/HL mapping, не отправлять их молча в другой handler.

## Правило статуса и следующий шаг

Все текущие PARTIAL/LEGACY_REVIEW строки имеют missing implementation; **BLOCKED_EXTERNAL сейчас не назначен ни одной форме**. Он допустим после UI+validation+serializer+callable configurable adapter+error/loading+tests, когда остался только реальный endpoint/аккаунт. Дальше: после общего inventory gate и P0.1–5 подключить единый runtime transport/context, затем по группам auth→profile/organization→business/support forms. Root владеет checkout/coupon и общими project memory files. Этот inventory не завершает recovery sprint.

Public GET evidence: [crawl-forms-compact.json](evidence/crawl-forms-compact.json), 4434 crawled URLs, 2273 distinct metadata schemas (not business-form count). No hidden/password/session values retained and no forms submitted.
