# Возврат товаров — 14.09.2026

## Объём и исходное состояние

Запрос владельца: RETURNS_MASTER_PROMPT.txt, 615 строк. Активная страница /pages/returns раньше содержала лишь краткий ReturnGuide с четырьмя общими раскрывающимися блоками. Заменена отдельным ReturnsPage; соседние страницы и app shell сохранены. Полный текст для покупателя разобран в RETURNS_COPY.json: 30 разделов. Верхняя группа и «Покупателю» представлены специальными компонентами, остальные разделы — напрямую из COPY. Материалы автора о реализации не публикуются как клиентский текст.

Равноправные вкладки B2C/B2B меняют показ правил; при переходе в заказы/формы выбранный режим применяется через существующий серверный buyer context. Для организации сохраняется её ID. В отсутствие организации используется business-контекст с выбором организации в кабинете. Переключение текста само по себе не меняет корзину.

## Изменения возвратной логики

1. В исходных шаблонах personal_returns_orders_list и organization_returns_orders_list (templates/.default/template.php:29–44) подтверждены универсальные 14 дней, запрет без даты вручения и ORDER_HAS_RETURN_TICKET. В мобильном WorkspaceDriver датового запрета уже не было; повторная заявка блокировалась в ServiceDriver.
2. ServiceDriver больше не запрещает второе обращение на весь заказ. Право доступа, принадлежность организации и товаров, завершённый статус сохранены. Для ещё не полученного заказа остаётся обращение; возврат денежных средств не выполняется автоматически.
3. ReturnWriter сохраняет новую заявку непосредственно в существующий IBLOCK_ID_RETURNS, совместимый JSON_RETURNS, ID товаров, причины, комментарии, медиа, номер и статус IN_WORK. Старый source HTTP handler, повторно запрещающий заявку, не вызывается. Форма работает только при включённом администратором runtime и установленном Bitrix.
4. Добавлено количество по каждой выбранной позиции. Максимум приходит из корзины конкретного заказа, допускаются дробные товары (до 3 знаков после точки). PHP проверяет границы повторно. Это количество требования, не автоматическое списание или возврат денег; повторная претензия по ранее заявленному товару сама по себе не отклоняется.
5. 10 файлов считаются на товар/поле, а не на весь заказ. 20 МиБ на файл, разрешённые фото/видео и проверка реального MIME/60 секунд сохранены. Общее хранилище ограничено отдельно (настраиваемая квота, 512 МиБ по умолчанию). Подтверждённые файлы связываются только со своим товаром; незаписанная заявка очищает созданные файлы.
6. WorkspaceDriver показывает товары, количество, причины и комментарии из JSON_RETURNS в существующей карточке заявки. Старые записи без количества читаются без выдуманной цифры.
7. Source-папка и архив не менялись. Для программистов подготовлен `integrations/runtime/source-patches/returns-intake-2026.patch`: два старых веб-шаблона, запрет повторной заявки в веб-обработчике и экранирование комментария в двух шаблонах деталей. Патч проверяется на исходнике, но на работающий сайт не применяется. «Забрать со склада до +14 дней» в dashboard не относится к возврату и намеренно не изменено.
8. Замороженные правила для выдачи: `integrations/runtime/return-rules-2026-09-14.html`. ReturnInformationReceipt регистрирует версию/хеш/заказ/продавца/канал/факт и подтверждающий документ. Его нужно вызвать из достоверного события вручения или подтверждённой доставки уведомления; не при открытии страницы/оформлении заказа. Повторная запись того же события не изменяет доказательство.

В шаблонах деталей исходного сайта подтверждён вывод COMMENT как необработанного HTML (строка 117). Исправление включено в source patch; запись через новый runtime требует returns.legacyTemplatesEscaped=true после применения и проверки патча.

## Границы проверки / подключение программистами

BLOCKED_BY_EXTERNAL_ACCESS: реальные вход, заказы, прием заявок, CRM/1С, статусные события и вручение правил. В preview нет живой БД Bitrix. Успешная отправка не имитируется. ReturnWriter протестирован на изолированных PHP-заглушках, а не на рабочих заказах. Клиентские формы и ссылки сохраняют существующую обработку недоступности сервиса; почта и телефон доступны без кабинета.

Не подтверждена динамическая привязка реквизитов продавца каждого реального заказа: сейчас показаны проверенные общие контакты ООО «Промышленник» и переход к документам заказа. При подключении магазина вывести фактического продавца из заказа, а не выбирать его по городу пользователя.

На серверном CLI PHP отсутствует PDO SQLite. Поэтому реальный PDO-тест ReturnInformationReceipt здесь не выполнен; модуль прошёл синтаксическую проверку, тест с памятью SQLite передан программистам. Это существующая предпосылка всего runtime, не причина устанавливать расширения в общий боевой сервер.

Это техническая сверка и реализация, а не заключение об отсутствии юридических рисков.
