## Фактическое хранилище и внешние сервисы preview

- `prom23-local-session-v2`: localStorage в web / SecureStore на устройстве; непрозрачный токен основной сессии, корзины, выбранного региона и явно запрошенных действий. В текущем preview автоматического TTL нет: до сброса/удаления хранилища; серверный срок хранения нужно определить перед production.
- `prom23-privacy-v1`: необходимая запись выбора категорий, редакции, времени выбора и истечения. Срок 180 суток — техническое решение этого preview. После истечения/невалидной версии все необязательные цели выключаются и запрашивается новый выбор; ручное изменение доступно раньше. Изменение в другой вкладке синхронизируется.
- Автоматическая история просмотров — до 30 идентификаторов товаров на режим; поисковая — до 10 запросов; только функциональный opt-in. Отказ прекращает запись, очищает историю на сервере при синхронизации и скрывает её немедленно в UI. При отсутствии сети очистка сервера произойдёт при следующем успешном обращении с отказом; не заявляется мгновенное удаление офлайн.
- Избранное сохраняется по явному действию при включённых функциональных cookie; отзыв cookie не трактуется как запрос на уничтожение ранее сохранённого списка. Для удаления данных используются предусмотренные обращения субъекта.
- В изменённом приложении не установлены GA4/Google Ads/Meta/VK Pixel/Метрика. В проверенных браузерных сценариях запросы шли только на origin preview; набор реально подключённых тегов боевого сайта неизвестен. Выбор аналитики/рекламы не устанавливает сторонний SDK автоматически.
- Каталог/доставка/оплата/формы сохраняют общий API и интеграционные ограничения. Bitrix-интеграция остаётся пропущенной по указанию владельца; никакие внешние письма, CRM-заявки, заказы или платежи во время проверки не создавались.

## Обязательные проверки перед запуском production

Следующие пункты матрицы нельзя закрыть проверкой изолированного preview:

1. Реальные способы авторизации и соответствующие обработчики персональных данных.
2. Фактический эквайер, СБП, Яндекс Пэй/Сплит, токенизация, привязка и повторное использование карт.
3. CRM/Битрикс/1С, телефония, SMS/email, службы доставки, DaData, ОФД/ККТ и фактические наборы передаваемых данных.
4. Физическое размещение баз в РФ, сроки хранения и удаления по каждой категории; текущий бессрочный preview-токен не является утверждённой политикой хранения production.
5. Полная инвентаризация cookie/localStorage/sessionStorage и тегов на production, включая сторонние виджеты и менеджеры тегов.
6. Реальные получатели/страны трансграничной передачи и вид/реквизиты уведомлений Роскомнадзора. Номер «разрешения» не выдумывался.
7. Фактический продавец в регионах, согласованность оферты/возврата/оплаты/доставки с новой редакцией. Проверка новых нормативных актов — отдельная юридическая задача; формулировки владельца не переоценивались.
8. Основание публичного распространения имени/отзыва; будущая модель сторонних продавцов, если появится.
9. Доставка реальных рекламных подписок, фиксация согласия и отказа в подключённых системах, восстановление cookie выбора/прав пользователя на всех production-поверхностях.
