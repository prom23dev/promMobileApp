# V7 — итог независимой проверки клиентских сценариев

11.09.2026, локальный `http://127.0.0.1:8087`, Expo Web в отдельном headless Google Chrome. **14 из 14 проверок прошли, exit 0.** При каждой прямой навигации проверялся bundle `entry-9bd376941d209cef85b2f91b43359fc7.js`; смешанные экспорты не принимались. Это результат перечисленных сценариев, а не процент качества продукта или допуск в магазины.

Основные доказательства: [машинный отчёт](qa-v7-report.json), [лог](qa-v7-run.log), [воспроизводимый сценарий](../mobile/scripts/browser-qa-v7.cjs). Скриншоты `qa-v7-failure-*` относятся к прежним прогонам и не являются результатом этого успешного кандидата. Исходные дефекты первого экспорта сохранены отдельно в [первом отчёте](qa-v7-initial.md) и `qa-v7-r1-*`.

В 22 снимках геометрии нет безымянных видимых controls и целей меньше 24 CSS px. Видимый фрагмент следующей категории в горизонтальной ленте при 320/390 является подсказкой прокрутки и не увеличивает ширину документа. Этот автоматический порог не означает соответствие всех целей нативным требованиям.

Нет `pageerror`. Внешние мутации блокировались маршрутизатором теста; попыток не зафиксировано. Из записей выполнялись только локальные `/api/sessions` и `/api/actions`. Внешние формы, заказы, платежи и системный телефон не активировались. Согласия в проверенной форме изначально выключены.

## Исправления и прагматическая оценка

Применены adversarial-ux-test и accessibility-compliance-accessibility-audit. Модельная персона — снабженец 56 лет, которому нужно передать спецификацию и понять поставку. Это симуляция, не исследование с настоящими покупателями.

Его основной путь теперь проходит без переобучения: виден телефон, поиск остаётся поиском, список переносится в КП, неизвестные позиции не исчезают. До подключения backend путь останавливается до реального обращения; это отдельный релизный блокер, который хороший интерфейс не снимает.

| Фильтр | Решение |
| --- | --- |
| RED — реальная проблема | Содержание спецификации в query первого экспорта создавало риск записи в URL/history. Исправлено на in-memory draft с opaque ID; повторная проверка пройдена |
| YELLOW — применимый принцип | Несколько H1 у главной ухудшали структуру. Исправлена иерархия, подтверждена в DOM |
| WHITE — не дефект продукта | Промежуточные HTTP503 во время экспорта и найденный в скрытом предыдущем stack-экране текст ошибки не доказывали поломку активной формы. Повтор выполнен на фиксированном bundle с учётом видимости |
| GREEN — без новой задачи | Частично видимую соседнюю категорию не убирать: она указывает на горизонтальную прокрутку. Автоматически сохранять коммерческие спецификации в persistent storage без отдельной модели данных не добавлять |

Новых подтверждённых UI-блокеров в этой матрице не осталось. Нативные, интеграционные и правовые блокеры остаются в [release](release.md), [security](security.md) и [store-compliance](store-compliance.md).

## Ограничения и следующий допуск

- Проверялся Chromium/Expo Web, не iOS Safari, IPA/AAB, VoiceOver/TalkBack или системный Dynamic Type. V6 browser scaling не перенесён на V7 как новый результат.
- `prefers-reduced-motion: reduce` подтверждён, взаимодействия в этом режиме работают. Не проводилось измерение всех анимационных кадров, native animation performance, полной контрастности и WCAG-сертификации.
- Нет доказанного соединения с production Bitrix24/1С, авторизацией, доставочными тарифами, платёжным провайдером и ККТ. Нет реальных отправок/деньговых операций.
- Отдельные unit-тесты спецификации/черновиков: 7/7, [лог](qa-v7-quick-order-tests.log). Общие сохранённые результаты V7: mobile 48/48, server 50/50; они не заменяют интеграционные испытания.
