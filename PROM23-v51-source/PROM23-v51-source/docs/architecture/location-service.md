# Location service — контракт MASTER4 / P0

Дата: 11 сентября 2026. Контракт согласован с владельцем native client и реализован в Node BFF. Основание: [аудит исходника](../audit/location-system.md). B2C и B2B равнозначны; guest personal — техническое начальное состояние, не ограничение возможностей организации.

## Решение и границы

Оставить существующий `/api/v1` и Node BFF. Добавить независимый модуль `server/location/`; не обращаться из приложения к PHP HTML handlers, не переключать hostname, не использовать ключи из архива. Получать официальный справочник вне пользовательских запросов, валидировать перед атомарной заменой локального индекса. Поисковый интерфейс не зависит от DaData; в P0 источник — проверенная выгрузка ФНС. При отсутствии/повреждении справочника вернуть 503, а не придуманные города.

| Сущность | Идентичность и поля | Источник истины |
|---|---|---|
| Settlement | `id`=официальный OBJECTGUID, `garId`=OBJECTID (строка), `fiasId`=тот же OBJECTGUID; name/type/typeShort, region, district, fullName, providerVersion | ГАР; отдельный адресный объект, не склад/филиал |
| ServiceRegion | внутренний ID, price policy, доступные способы доставки/оплаты; срок/версия mapping | Активные регионы Bitrix и согласованная таблица соответствия; **сейчас unavailable** |
| Warehouse | ID, адрес, график, координаты, pickup, реальные остатки | StoreTable/StoreProductTable и региональные связи; **сейчас unavailable** |
| DeliveryAddress | Settlement ID + street/house/building/flat/postalCode/comment, owner/org scope, Bitrix LOCATION_CODE при подтверждённом mapping | Отдельный приватный ресурс; выбор населённого пункта не создаёт адрес |

`region` в Settlement — административный субъект, `district` — район по официальной иерархии. Это не ServiceRegion. Географические UUID — идентификаторы, не разрешение на цену/склад. Неизвестные связи возвращаются null/unresolved, ни Краснодар, ни ближайший филиал не подставляются.

## Реализованный контракт

Все ответы используют существующий `{data: ...}` / `{error:{code,message}}`. JSON, строгие поля, ограничение размера, отсутствие raw errors. Публичный поиск без пользовательских данных; выбор хранится в текущей sandbox-сессии до подключения настоящей авторизации.

| Endpoint | Данные | Инвариант |
|---|---|---|
| `GET /api/v1/locations/suggest?q=&limit=10` | `{items: Settlement[], query, coverage, providerVersion}` | q — только поисковая строка, не сохраняется. limit 1–20; неизвестные/повторяющиеся параметры запрещены. |
| `GET /api/v1/locations/:id` | Settlement, только точный UUID из активного индекса | Вымышленный/исключённый/устаревший ID не принимается. |
| `GET /api/v1/location` | `{version, settlement, recent, commerce, cartValidation}` | Только текущая сессия; старое city string не считается подтверждённым выбором. |
| `POST /api/v1/location` | `{settlementId, expectedVersion, expectedContext}` → новое состояние | ID-only, compare-and-set; 409 при устаревшей версии/контексте. Обновить display city совместимости, но не цену. |
| `POST /api/v1/cart/revalidate-location` | `{expectedVersion, expectedContext}` | Пока 503 `LOCATION_INTEGRATION_REQUIRED`; позиции не меняются, заказ не создаётся. |

`commerce = {status:'unresolved', serviceRegion:null, warehouses:[], deliveryMethods:[], paymentMethods:[], reason:'BITRIX_MAPPING_REQUIRED'}`. `cartValidation = {status:'required', checkoutEligible:false, reason:'BITRIX_REVALIDATION_REQUIRED'}` после выбора; сохранение населённого пункта не означает успешный пересчёт.

Структурная миграция: отдельная session-owned запись `session_locations` с FK ON DELETE CASCADE, монотонной версией и recent ≤8 ID. Смена B2C/B2B не стирает выбор. Корзины обоих контекстов сохраняются. Все неиспользованные котировки этой сессии отзываются атомарно после выбора; исторические использованные котировки/заказы остаются. Новый quote нельзя выдавать как проверенный по snapshot. Legacy `/api/actions` с type=city отклоняет свободный текст (`SETTLEMENT_SELECTION_REQUIRED`); исключение — явно включённая конструкторами изолированных тестов fixture-mode. Географические методы зарегистрированы в `server/app.mjs`; consumer commerce gates остаются закрытыми.

## Поиск и выбор

Индекс содержит реальные типы населённых пунктов. Ё/е, регистр, Unicode/пробелы нормализуются для поиска, но официальное имя в ответе не переписывается. Точное совпадение выше префикса, затем ограниченная опечатка; латинская транслитерация и ошибочная раскладка создают варианты запроса, не фальшивые aliases. Одноимённые записи остаются отдельными и показываются с субъектом/районом/типом. Поиск не создаёт новую запись. Пустой запрос может показывать проверенные популярные/недавние варианты; «нет результата» различает отсутствие в локальном покрытии и недоступность провайдера.

В клиенте only explicit suggestion tap сохраняет ID. Enter по тексту не подтверждает адрес. Отмена оставляет прежний выбор. Перезапуск берёт выбранный объект с сервера/валидируемого cache. Полный адрес, улица и дом не отправляются в поиск населённых пунктов автоматически.

## Импорт и заменяемость

Интерфейс провайдера: readiness/provenance, `suggest(query,limit)`, `getById(id)`. Локальный индекс проверяет schemaVersion, source URL allowlist, официальные UUID/числовые OBJECTID, уникальность и актуальность записей, связи региона/района. Импорт — отдельная CLI, не обработчик web-запроса. Разрешены только HTTPS ФНС, ограниченные загрузки, CRC/size проверка ZIP, XML без внешних сущностей, никакого исполнения PHP. Все метаданные выгрузки сохраняются; coverage должна честно сообщать неполный импорт.

Полная административная иерархия нужна для гарантированной дизамбигуации. Импорт обошёл все 96 региональных папок официальной выгрузки; промежуточный extract 23/77/78 явно сообщал coverage=partial. Нельзя заменять пробел в данных придуманным районом. Подключение другой службы подсказок требует server-only конфигурации и отдельной проверки полей, но не меняет DTO приложения. Секретов/default credentials нет.

Непосредственно проверенное уточнение схемы ГАР: `ISACTIVE=false` у строки **словаря типов** не означает неактивность адресного объекта. В базе есть active/actual LEVEL5/6 с прежними сокращениями типов. Согласованная политика — сохранять название такого типа из официального исторического словаря при активном актуальном объекте и проверенной текущей ADM-цепочке. Никакого собственного переименования СНТ/территории в город. В manifest отражается `typeDictionaryPolicy` и число объектов с историческим типом; inactive/неactual объекты по-прежнему исключаются. Индекс покрывает официальные объекты уровней «Город»/«Населённый пункт», включая встречающиеся в ГАР территории с явным типом, и федеральные города уровня 1.

## Миграция и последующее подключение Bitrix

Cookie region.id — коммерческий регион, не Settlement ID; PERSONAL_CITY — свободная строка; FULL_ADDRESS — приватный адрес. Автоматический перенос допустим только при единственном официальном совпадении с достаточным региональным контекстом. Иначе предложить варианты пользователю. Не записывать unknown string как подтверждённый Settlement. Для входа после guest переносить подтверждённый выбор с версиями и явной политикой конфликта с профилем; до реального auth это контракт, а не реализованный сценарий входа.

Bitrix adapter впоследствии получает user/org/FUser из авторизации, Settlement ID и подтверждённый Warehouse ID. Он разрешает location code по официальному mapping без `TYPE=CITY` исключения других типов, вычисляет ServiceRegion и price codes, вызывает существующий BasketUsers/CatalogProvider, сравнивает прежние/новые суммы, наличие, доставку и оплату. Возвращает изменения для подтверждения. Quote связан с locationVersion, cartVersion, context и expiry. Неизвестные остатки остаются unknown. Source B2C DEFAULT_CITY не переносится.

## Проверки P0 и граница приёмки

План: официальные IDs и provenance; Динская/город/село/посёлок/хутор; одноимённые места; ё/е, typo/translit/layout, пустой/несуществующий/длинный запрос; отказ сохранения текста/чужого ID; session/context/version isolation; persistence/reopen, recent dedup, delete cascade; изменение места сохраняет корзину и делает checkout непроверенным; unavailable provider не создаёт фальшивый выбор. Без действующего Bitrix нельзя отмечать реальный региональный пересчёт/доставку/заказ пройденными.

Выполнено: 12 geo unit/HTTP тестов (в том числе изоляция, CAS, сохранение двух корзин, отзыв старых quote, повторное открытие SQLite, guest без default selection, точная/неоднозначная legacy миграция без GET-записи, foreign Origin, oversize JSON, удаление сессии, недоступность provider/revalidation). Совместный запуск API/public-v1/geo — 53 PASS на Node24; [лог](../location-api-tests-master4.log). Импортёр: 8 offline проверок CRC/size, XML/chunk boundary, ID-фильтра, URL allowlist, inactive/current level ([лог](../location-import-tests-master4.log)). Эти проверки не являются реальным Bitrix checkout или native device приёмкой.

## Эксплуатация локального справочника

`python3 server/location/import-gar.py --output server/location/data/gar.sqlite --workers 3` — явная CLI-команда загрузки официальной публичной базы. До запуска проверить свободное место под два индекса; XML не сохраняется. Повторный полный импорт собирается в `.building`, затем публикуется через атомарную замену; незавершённая работа не подменяет исправный индекс. `--regions 23,77,78` ограничивает выборку и оставляет coverage partial. `--extend-existing` разрешает переимпорт выбранных папок только при той же версии/ETag; не смешивает разные выпуски.

Runtime constructor: `garDatabasePath` (по умолчанию `server/location/data/gar.sqlite`). Индекс открыт read-only; SQLite cache2MiB, mmap отключён. Переоткрытие после атомарной замены проверяется не чаще раза в3секунды. Повреждённая/отсутствующая база даёт503 поиску; запуск BFF не блокируется. Runtime-сессии остаются в отдельной SQLite с собственными квотами. В deploy allowlist включены только provider/service + официальный индекс/manifest; импортёр не запускается службой и не требует секретов. Эта подзадача ничего не размещала на сервере и не меняла DNS/production.

Итоговый артефакт:160478записей,96/96папок,0неразрешённых записей;173752320байт SQLite (165,70MiB). Полный manifest и контрольная сумма зафиксированы в [location-tests.md](../testing/location-tests.md). Микрозамер60последовательных поисков по этому реестру: p50=1,915мс, p95=13,922мс, max=29,5мс; RSS процесса64,11MB. Это in-process измерение текущей машины, не нагрузочный HTTP-тест или приёмка мобильной производительности.
