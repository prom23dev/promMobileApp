# Mobile checkpoint V7

## Контекст и решения до UI

iOS + Android; существующий Expo/RN клиент. Основные покупатели: частный покупатель и снабженец/владелец компании. Заказ может содержать тяжёлое оборудование и требовать инженерного расчёта. Основной риск — показать лёгкий розничный интерфейс ценой потери B2B-контекста.

- **Навигация:** сохраняем 5 знакомых вкладок (главная, каталог, избранное, корзина, кабинет), поскольку все востребованы в повторных покупках. Полезный контент — через видимые тематические блоки и «Ещё»; поиск остаётся TextInput, звонок/контакты доступны постоянно.
- **Лента:** виртуализированные блоки главной и товарные списки; ограниченный горизонтальный ряд категорий/подборок. Не загружаем 100k SKU в клиент и не отрисовываем их ScrollView.
- **Состояние:** общая корзина/контекст/история, локальные состояния раскрытия; серверные роли, цены и доступы не выводятся из локального выбора «для компании».
- **Первый экран:** отраслевой тезис + реальное оборудование/производство + один основной CTA. Никаких общих «лучшее качество» и неподтверждённых счётчиков.
- **iOS:** safe-area, возврат через native stack, Dynamic Type, системная клавиатура/Share, VoiceOver; никаких CSS-эффектов вместо native компонентов.
- **Android:** системный Back, 48dp touch, TalkBack, fontScale до 2, системные разрешения по действию; оценка predictive back в native build.
- **Motion:** только transform/opacity на native driver; один переход героя, обратная связь на выбор, раскрытие по нажатию; reduced-motion и отмена эффектов при unmount. Не имитировать загрузку задержкой.
- **Офлайн:** каталог/контент из проверенного кеша и гостевая корзина; оформление, оплата и изменение прав только online с подтверждением сервера.

## Декомпозиция

| Экран | Главное действие | Touch / доступность | Нагрузка / состояние |
|---|---|---|---|
| Главная | Найти оборудование / запросить комплектацию | 48dp кнопки, описательные названия, H1/H2, возврат из каждого перехода | FlatList секций, ограниченные реальные фото, асинхронная конфигурация с fallback |
| Каталог | Открыть подходящий товар | Поиск отдельно от меню; фильтры с применением и сбросом | Пагинация по контракту, memo rows, ограничения payload |
| Товар | Добавить / уточнить комплектацию | Нижний CTA, сравнение/избранное, понятная цена и единица | Фото по размеру, нет fake stock, доставка/платёжные данные с TTL |
| B2B | Передать ТЗ / спецификацию | Минимальные поля, объяснение результата, доступный звонок | Проверка количества/SKU, неизвестные строки остаются явными |
| Корзина | Проверить и оформить | Раздельные личная/организация, ошибку можно исправить | Integer kopecks, server reprice, не скрывать недоступность checkout |
| Кабинет | Войти ради заказов/документов | До регистрации объяснить пользу, гость может обращаться | Только реальные данные после auth; SecureStore для refresh token после issuer |

## MFRI / честная готовность

UX-контекст и клиентская архитектура определены; инфраструктура live commerce не готова. Высокий риск интеграции и корпоративных прав, средний риск изображений/длинных списков, низкий риск обычных контентных экранов. Процент «идеала» не является измерением: приёмка идёт по сценариям, визуальным дефектам и замерам, с отдельным статусом native-проверки.

В skill встречаются устаревшие/неточные универсальные примеры (например, WCAG 2.5.8 назван 44px). Для проекта 48dp/44pt — собственный консервативный touch-стандарт; юридические/платформенные нормы проверяются по актуальным официальным источникам, а не копируются из примера.
