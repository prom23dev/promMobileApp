# Архитектура и первый срез

Дата: 11.09.2026. Это проектная основа; интеграция и выпуск пока не выполнены.

## Архитектурное решение

React Native + Expo + TypeScript: один код интерфейса с нативными элементами для iOS и Android. Выбор предварительный, окончательно проверяется совместимость банковского SDK, СБП, карт, документов и устройств. PHP/Bitrix остаётся источником цен, остатков, прав доступа и заказов. Приложение не обращается к HTML-формам сайта как к API.

Мобильный BFF `/mobile/v1` — отдельный версионируемый серверный слой на стороне Bitrix. Сайт и приложение используют одни бизнес-сервисы. Этот слой не реализован в текущем первом срезе: без работающей базы нельзя проверить его корректность.

- Публичный каталог: поиск, категории, фильтры, сортировка, курсорная пагинация, ETag; сжатые изображения с заданными размерами.
- Авторизация: одноразовый код, лимиты по номеру/устройству/IP, TTL, анти-перебор. Access token в памяти, rotating refresh token в Keychain/Keystore, отзыв сессий на сервере. Секреты поставщиков только на сервере.
- B2B: сервер проверяет членство и полномочия на каждом запросе; ИНН не является доказательством доступа. Организационный контекст входит в ключи кеша, корзины, адресов, документов и заказов. Смена контекста отменяет прежние запросы, очищает приватный кеш.
- Деньги: целые копейки. Цены, НДС, скидки, доставка и итог всегда пересчитываются сервером. Клиент передаёт SKU и количество, а не доверенные цены. Ставку НДС клиент не зашивает.
- Checkout: серверная котировка с TTL и версией, затем создание заказа с idempotency key, привязанным к пользователю, контексту и хешу запроса. Повтор ключа с другим телом отклоняется. Повтор запроса после таймаута не создаёт второй заказ.
- Оплата: SDK/защищённая платёжная страница выбранного банка, либо СБП. PAN и CVV не проходят через приложение или сервер магазина. Статус оплаты подтверждает серверный webhook с проверкой подписи, суммы, валюты и идентификатора. Deep link лишь возвращает пользователя в интерфейс.
- Документы: короткоживущие ссылки после проверки прав; скачивание в защищённую область, явное действие «Поделиться». Никаких публичных счетов по предсказуемому ID.
- Push: минимальное содержимое без реквизитов и персональных данных; разрешение при понятной пользе, категории сервисных и рекламных уведомлений разделены. Архитектуру APNs/FCM и трансграничной передачи проверяют отдельно.
- Конфиденциальные данные не пишутся в логи/аналитику. Данные физлиц и контактных лиц компаний учитываются одинаково как персональные.

## Дизайн

Основа — цвета `site-source/frontend/sources/style/modules/mixins.scss`: синий `#3D4471`, оранжевый `#FF4016`, фон `#F2F7FB`. Для читаемого текста и кнопок добавлены тёмный `#202747`, акцент `#BD2D0B` (контраст с белым выше, чем у исходного оранжевого), белый `#FFFFFF`. Оранжевый сайта сохраняется для знака и графических акцентов. Типографика — системные San Francisco/Roboto с отдельными ролями заголовков и текста: без блокирующей загрузки шрифтов и без переноса непроверенной лицензии RF Dewi.

Характерная деталь — схематичная конструкция строительных лесов в карточках. Это иллюстрации, а не фотографии товаров. Реальные фото отсутствуют в архиве. Демонстрационные названия, цены и остатки не являются коммерческим предложением.

```
Промышленник              город
[ Для себя | Для компании       ]
[ Поиск по названию и артикулу  ]
[ Категории →                   ]
Название подборки        сортировка
[ товар        ][ товар         ]
[ цена         ][ цена          ]
Главная · Каталог · Избранное · Корзина · Кабинет
```

Для приложения важнее плотность полезной информации, доступность и скорость, чем большой рекламный hero. Сенсорные цели от 44 pt, озвученные кнопки, системное масштабирование текста, отсутствие обязательной анимации. Нативную доступность нужно проверить с VoiceOver/TalkBack.

## Измеримые цели, а не обещание скорости

Предварительные критерии согласуются на этапе приёмки. Это цели, замеров пока нет:

| Сценарий | Цель | Условия измерения |
|---|---|---|
| Холодный запуск до доступной навигации | p95 ≤ 2,5 с | Release, физические iPhone и Android среднего класса, 30 запусков |
| Открытие кешированной карточки | p95 ≤ 300 мс | 30 переходов, тёплый кеш |
| Поиск после debounce | p95 ≤ 1 с | RTT 100 мс, ответ API; отдельно считать сеть и рендер |
| Прокрутка каталога | ≥ 95% кадров в бюджете 16,7 мс | 60 Гц, 500 SKU, локально кешированные изображения |
| Публичный API каталога | p95 ≤ 400 мс | Согласованная нагрузка, измерение на сервере |
| Стабильность | ≥ 99,8% сессий без аварий | По реальной бете; обезличенная телеметрия после проверки |

Для этого нужны пагинация/виртуализация, ограниченный кеш, отмена неактуальных запросов, индексы поиска, оптимизация SQL/Bitrix и CDN в согласованной инфраструктуре. Сравнение с WB/Ozon/Яндекс Маркет возможно только по одинаковым сценариям, устройствам и сети.

## Блокеры полной реализации

Нужны адрес тестового сайта, тестовые роли, база/ядро Bitrix, права на доработку API, договоры и sandbox выбранных поставщиков, каталог/фотографии, реквизиты оператора данных, правила B2B доступа и удаления данных, аккаунты магазинов. На этом компьютере нет полного Xcode/iOS Simulator; native build и device QA здесь ещё не выполнялись.
