# PROM23 — discovery перед V7

Дата: 11 сентября 2026 года. Основание: пользовательский master plan из `pasted-text.txt`, исходный архив и опубликованные страницы `prom.myfast.space`. Этот отчёт составлен **до изменения UI V7**. Детальные свидетельства: `discovery/visual-audit.md`, `discovery/backend-audit.md`, `discovery/source-*-rendered.json`, предыдущий построчный аудит `01-source-audit.md` и карта `21-content-navigation.md`.

## Вывод

Сохраняем Bitrix как источник коммерческих правил и строим мобильный клиент с явным BFF. Переписывание магазина или перенос браузерных webhook-ключей в приложение неприемлемы. В архиве нет ядра Bitrix, БД, upload и полного окружения: это кастомизация магазина, а не запускаемый дистрибутив.

Главная V6 выглядела как малый каталог из одинаковых карточек. Она скрывала настоящие отличия компании: производство, крупные стройки, инженерную компетенцию и поставку по спецификации. Увеличение радиусов или числа анимаций не решает эту проблему. V7 строится вокруг реального оборудования и производства, затем выводит товарную сетку, B2B-сценарий, проекты и условия покупки в отдельном ритме.

## Метод и границы наблюдения

- Изучены 2 343 файла архива; PHP не исполнялся. Названия, формы, поля, модели, события и интеграции проверены по коду; это не подтверждает состояние живой базы.
- Публичные главная, производство, компания, бизнес, проекты, бренды, каталог и контент проверены GET-запросами и в мобильной/настольной вёрстке. Скриншоты сохранены в `discovery/screenshots/`.
- `prom23.ru` проверяется отдельно как текущий домен; он не считается синонимом временного сайта. Переезд домена/DNS не входит в развёртывание V7.
- Вход, SMS, создание организаций, реальные заказы, CRM, рассылки, доставка и платежи на исходном сервере не выполнялись. Для них нет разрешённой изолированной staging-среды и тестовых данных.
- Опубликованный `/about/` содержит шаблонные отзывы; историческое основание в 2008 году не равно запуску собственного завода в 2008 году. Подтвержденная хронология: строительство заводов в 2021, очереди производства в 2022–2024.

## Архитектура и структура

`mobile/` — Expo / React Native, native navigation и UI, общий типизированный domain. `server/` — ограниченный BFF, адаптеры и контрактные тесты. `integrations/bitrix/` — серверный мост, ключи только в окружении сервера. `data/` — версионированный публичный контент с provenance. `docs/` — ADR, схемы, матрицы соответствия и приёмка. `deploy/` — изолированное атомарное обновление и rollback.

Сравнение React Native, Flutter и двух native-команд: `adr/001-mobile-stack.md`. React Native рассматривается как сохранение уже существующего работоспособного клиента и TypeScript-контрактов, а не как универсально лучший стек.

## Порядок реализации

1. **Discovery / до кода:** данный отчёт, визуальная критика, матрица функций, ADR, аудит безопасности и магазинов.
2. **Foundation:** семантические токены, компоненты, ограниченный CMS-контракт главной, BFF v1/capabilities, отсутствие автоматического успеха для неподключённых сервисов.
3. **Вертикальный сценарий:** запуск → главная → поиск → каталог → товар → корзина → авторизация → оформление. Пока нет staging backend, последняя операция должна явно завершаться состоянием недоступности, без номера/статуса реального заказа.
4. **Коммерческие модули:** проверенные организации/роли, серверные цены/остатки, checkout, платежи и доставка, история, документы, повтор/возврат, согласия. Зависимость — изолированный Bitrix staging и sandbox провайдеров.
5. **Удержание:** история/релевантные рекомендации, подбор по задаче, КП со спецификацией, проекты и статьи, кабинет с понятной пользой. Без препятствий выходу, ложного дефицита и автоматических сообщений.
6. **Приёмка / выпуск:** контрактные и браузерные сценарии, signed native build, тесты на реальных iOS/Android, VoiceOver/TalkBack и performance; сверка юридических реквизитов и магазинов; затем публикация.

## Текущие внешние блокеры

Нет ядра/БД Bitrix, mobile token issuer, подтверждённых staging B2C/B2B аккаунтов, sandbox платежей/логистики, ключей APNs/FCM/RuStore, сертификатов подписания и единого подтверждённого оператора ПД. Отсутствие этих данных не мешает закончить дизайн, клиент, контракты и безопасный стенд; оно мешает честно назвать приложение принимающим реальные заказы и готовым к публикации.

V7 заменяет только `prom23-preview.service` на `159.253.19.172:18087`. `zavod-antibpla.ru`, DNS и общие веб-службы не изменяются. До/после обновления проверяются хеши файлов и состояние служб боевого сайта.
