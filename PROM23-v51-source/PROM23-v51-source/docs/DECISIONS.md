## ADR-026 — Business intent и организация
STATUS: ACCEPTED — реализация исходной модели.
`business` — отдельная корзина намерения закупки, а не придуманная организация. `organization:<ID>` включается только после серверной проверки принадлежности организации авторизованному пользователю. Смена context сохраняет личную корзину. Проверки source membership/cache не заменяют actor authorization.

## ADR-027 — Подтверждённые суммы и варианты
STATUS: ACCEPTED.
Сумма каталога является предварительной. Подтверждённый quote привязан к точному составу/количествам, организации, GAR/version, адресу, способам получения/оплаты и купону. Изменение параметров отзывает quote. Сервер проверяет арифметику, строки, срок, canonical consent. Реальные пункты/перевозчики приходят из source runtime; отсутствие конфигурации возвращает ошибку без fake totals/success.

## ADR-028 — Проверяемые формы и транспорт
STATUS: ACCEPTED.
BFF использует отдельный HTTPS runtime с allowlist origin и подписанными запросами. Actor привязан к непрозрачной серверной сессии; source secrets и произвольные userId не принимаются от клиента. Формы используют versioned schema, canonical consents, source targets и upload tokens. Транспорт сам по себе не означает восстановление backend функции.

## ADR-029 — Срок платёжной ссылки и повторное открытие
STATUS: ACCEPTED — correction from source lifecycle.
Invoice one-use tickets and saved Split references use their own fresh ownership/expiry/durable-state checks instead of generic cached URL replay. Other PSP writes retain generic idempotency pending/result protection. Never trust a client preference to choose the bypass. Verified by PHP08 isolated tests, not live PSP acceptance.


## ADR-030 — Компактное меню и transient feedback места получения

STATUS: ACCEPTED — focused sprint 00, явное поручение пользователя.

Проблема: текстовые строки плохо сканировались; уведомление места получения оставалось до ручного закрытия.

Решение: reusable MenuRow с единой Lucide-пиктограммой, минимум 54 px, переносом текста, компактным разделителем и скрытыми декоративными иконками. Состав/маршруты меню задаются прежним inventory. В меню один primary call quick action; на других экранах сохраняется contextual header call (showCall default true).

TransientNotice живёт только в памяти App Shell. Дедлайн — 4000 ms от события, повторный render его не продлевает; auto-exit 140 ms, X сразу удаляет компонент. Enter 160 ms / translateY не более 6 px. При Reduce Motion нет анимации. Cleanup отменяет предыдущий таймер, dismissal привязан к event ID; hydration не воспроизводит прошлое событие. Полное удаление освобождает layout. Polite announcement не переносит фокус.

Причина: быстрый обзор меню без потери возможностей и конечная обратная связь без постоянного баннера. Текст описывает сохранённую корзину и необходимость подтвердить цену/наличие/доставку, поскольку автоматическая connected revalidation не подтверждена. Решение не меняет backend и не является разрешением редизайнить другие экраны.

Проверка: 137/137 local + 137/137 public при 320/390 px; `parity/FOCUSED_SPRINT_00.md`.

## ADR-032 — Сотрудничество как хаб пяти исходных сценариев

STATUS: IMPLEMENTED — визуальная приёмка пользователем не получена.

Новый focused brief имеет приоритет над графическими баннерами ADR031 только для сотрудничества. Утверждённый copy хранится отдельно и не переписывается. Пять направлений ведут в существующие Business, procurement list/selection, Suppliers и Franchise; конечные контакты и телефон сохраняются. Общие страницы не редизайнятся. Существующая реальная фотография цеха заменяет абстрактные SVG.

Scroll narrative использует Animated.Value только для cooperation ScrollView; элементы измеряют свою позицию, линия/иконка/короткое смещение связаны с прокруткой. При Reduce Motion всё статично и полностью читаемо. Текст по умолчанию виден; приложение не ждёт анимации для доступа к информации. Header.heading default true; только cooperation использует hero H1 вместо второго H1 в appbar.

Upload observer опционален: прогресс увеличивается по подтверждённому nextOffset, проверка файла и completed token различаются. Ошибка сохраняет файл и ввод, retry повторно валидирует форму и использует прежнюю idempotency/cache для уже загруженных файлов. В web FileDropZone сохраняет сам File/Blob, чтобы прочитать bytes без запрещённого CSP fetch(blob:); CSP не ослаблена.

Исправление выявленного дефекта связанных форм: supplier/partner CTA передают текущий buyer context, а не принудительный business. Иначе B2C-посетитель получал STALE_CONTEXT ещё до отправки. Проверка несовпадения context и server membership сохраняются. Ни аккаунт, ни корзина не переключаются этим информационным переходом.


## ADR-033 — Осмысленная вертикальная scroll-анимация контентных и сервисных страниц

STATUS: ACCEPTED — прямое решение пользователя в delivery07, пункты1/69.

ALL CONTENT/SERVICE PAGES MUST USE MEANINGFUL VERTICAL SCROLL ANIMATION.

Основной storytelling направлен вниз. Появление секций, последовательная активация маршрута/иконок и соединяющих линий объясняют структуру, не задерживают чтение и действия. Только короткие opacity/transform; никакого bounce, бесконечных циклов, тяжёлого3D или горизонтальной карусели вместо истории. Обязателен Reduce Motion: все данные и действия доступны сразу, без движения. Цель60FPS проверяется профилем, а не объявляется гарантией на всех устройствах.

Правило применяется к последующим работам по контентным/сервисным страницам. В этом bounded sprint реализуется только доставка; это не разрешение менять остальные страницы. ACCEPTED относится к правилу, а не визуальной приёмке страницы.
