# Локальный API приложения

Обновлено 11.09.2026. Реализация `server/` — самостоятельный sandbox на Node.js 24 и SQLite, а не восстановленный сервер Битрикса. В ней нет боевой авторизации, доступа к реальным организациям, платежей, чеков, фактической доставки, 1С, ЭДО или отправки сообщений. Создание обращений и возвратов заблокировано до подключения справочников и процессов собственного сайта; произвольные темы/причины не заменяют их. Соответствие магазинам приложений и законодательству для production этим API не подтверждается.

## Запуск и остановка

В установленном Node.js 24:

```sh
cd /Users/prom23/Projects/prom23-mobile/server
/Users/prom23/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node index.mjs
```

При Node.js 24 в `PATH` достаточно `npm start`. Внешние npm-зависимости не нужны. Проверка: `http://127.0.0.1:8090/health`. Остановка в том же терминале: Ctrl+C; процесс штатно закрывает HTTP и SQLite. Никакого фонового автозапуска этот пакет не устанавливает.

CLI всегда слушает **127.0.0.1**, по умолчанию порт **8090**. `PROM23_PORT` позволяет выделить другой порт. Он не меняет интерфейс, на котором слушает процесс.

`PROM23_ALLOWED_ORIGINS` — JSON-массив **точных** разрешённых origin. Значение заменяет стандартный список. Пример для отдельного локального web preview:

```sh
PROM23_PORT=18090 PROM23_ALLOWED_ORIGINS='["http://127.0.0.1:18087"]' node index.mjs
```

Стандартный список: `http://127.0.0.1:8087`, `http://localhost:8087`, `http://127.0.0.1:8081`, `http://localhost:8081`. Схема и порт входят в сравнение; `*`, `null` и URL с путём запрещены. Нативные клиенты могут отправлять запросы без Origin. Заголовкам `X-Forwarded-*` приложение не доверяет и не использует их для идентификации.

Размещение на другом сервере требует отдельного каталога, пользователя процесса, службы, свободного порта и прокси с ограничением доступа. Этот пакет не содержит команд изменения доменов/DNS/существующих сайтов и не должен заменять службы `zavod-antibpla.ru`. Планируемая схема тестового доступа — только SSH-туннель на локальный `localhost:8088`, отдельный удалённый loopback-прокси на порту 18087 и API на 18090, без публичного порта и домена. Команды развёртывания находятся вне этого пакета.

Встроенные квоты хранения описаны ниже. **Ограничителя частоты запросов в API нет**. Если схема доступа изменится на внешнюю публикацию, потребуются внешняя аутентификация и rate limit в прокси или эквивалентном защитном слое; выставлять этот API напрямую в интернет нельзя. Loopback и CORS сами по себе не являются авторизацией внешнего тестового стенда.

## Данные и сохранение

- Снимок товаров читается при старте из `data/catalog.json` в корне проекта. Поддерживаются массив Product либо `{products, importedAt}`. Новый снимок применяется после перезапуска API.
- Каталог содержит цены **в копейках**. `imageFile`, `sourceUrl`, `importedAt`, `availabilityText`, `priceSource`, `stockSource` сохраняют происхождение импорта. `stock` — ограничение количества для теста, не обещание актуального остатка магазина.
- Если файл отсутствует или некорректен, API остаётся доступным, каталог пуст, а `/health` явно возвращает `catalogLoaded: false` и `catalogSeedStatus: missing|invalid`. Подмены вымышленным товарным каталогом нет.
- Рабочая БД: `server/data/runtime.sqlite`; каталог `server/data/` исключён из Git. Состояние сохраняется между перезапусками. Копировать БД для резервной копии следует после штатной остановки API; при работающем процессе учитывать SQLite WAL.
- Токен локальной сессии — случайные 32 байта в base64url. В БД хранится только SHA-256 токена. Это механизм изоляции sandbox, а не вход в настоящий аккаунт магазина. Утраченный токен нельзя восстановить через почту или телефон.
- `personal` и `organization-demo` — два тестовых контекста одной сессии. Режим организации не даёт доступа к реальной компании. Корзины, заказы, обращения и возвраты разделены по контексту; избранное и сравнение общие внутри сессии.
- Адреса — неизменяемые вымышленные примеры, отдельные для каждого контекста. API не собирает телефоны, платёжные реквизиты, пароли или реквизиты компаний. Тексты новых обращений и возвратов не сохраняются; ранняя тестовая история, если она существует, доступна только своей сессии и контексту.
- Удаление сессии отзывает токен и логически удаляет её записи из всех связанных таблиц. Оно не удаляет аккаунт на сайте, файлы резервных копий или данные вне этой SQLite-БД. Физическая очистка носителя не заявляется.

## Квоты тестового стенда

| Ограничение | Значение по умолчанию | HTTP 429 code |
|---|---|---|
| Все локальные сессии | 500 | `SESSION_LIMIT` |
| Заказы одной сессии, оба контекста вместе | 100 | `ORDER_LIMIT` |
| Сохранённые расчёты одной сессии | 200 | `QUOTE_LIMIT` |
| Основной файл SQLite | 8192 страницы × 4096 байт = 32 МиБ для новой БД | `STORAGE_LIMIT` |

Новые обращения и возвраты не создаются, поэтому роста этих таблиц через HTTP нет. При создании нового расчёта сервер удаляет только **истёкшие неиспользованные расчёты этой сессии**. Использованные расчёты, заказы и ранние обращения/возвраты автоматически не удаляются. Превышение квоты не очищает корзину или историю. Идемпотентный повтор уже созданного заказа работает и после достижения квоты заказов. Удаление своей локальной сессии освобождает её места в квотах.

`PRAGMA max_page_count` устанавливается при каждом открытии SQLite. Если существующая БД уже превосходит лимит страниц, запуск завершается ошибкой, без удаления данных. Новая БД создаётся с размером страницы 4096 байт; лимит основной БД не является жёсткой квотой общего каталога на диске: временный WAL/SHM занимают дополнительное место. Включены checkpoint каждые 100 страниц WAL и `journal_size_limit=1048576` для сохранённого журнала. Для общей файловой квоты нужны средства ОС.

Для интеграционных тестов `createApp({limits: {...}})` принимает частичные положительные целочисленные настройки: `maxDatabasePages`, `maxSessions`, `maxOrdersPerSession`, `maxQuotesPerSession`. Параметр ранней версии `maxAppealsPerSession: 100` сохранён для совместимости конфигурации, но не разрешает создание обращений: маршрут всегда заблокирован до интеграции. CLI использует приведённые значения по умолчанию. Настройки квот не поступают от HTTP-клиента.

## Контракт

Все успешные JSON-ответы: `{data: ...}`. Ошибки: `{error: {code, message}}`. Время в ISO 8601 UTC. Денежные значения — целые копейки, валюта `RUB`. В POST требуется `Content-Type: application/json`; максимальный размер — 32 КБ. Запросы с неизвестными полями/неподдерживаемыми методами отклоняются.

| Маршрут | Тело / результат | Доступ |
|---|---|---|
| `GET /health` | `status`, `mode`, `catalogLoaded`, `catalogSeedStatus`, `productCount`, `message` | Без токена |
| `GET /api/catalog` | `{products, categories, importedAt, mode: 'local-sandbox'}` | Без токена, только чтение |
| `POST /api/sessions` | Тело `{}` → `{token, state}` | Создаёт локальную сессию |
| `GET /api/state` | `ShopState` | Bearer |
| `POST /api/actions` | Действие ниже → новый `ShopState` | Bearer |
| `POST /api/quotes` | `{context, deliveryMethod: 'pickup'|'courier', addressId?}` → Quote | Bearer |
| `POST /api/orders` | `{quoteId}`, обязательный `Idempotency-Key` → Order | Bearer |
| `GET /api/orders` | Массив заказов текущего контекста, новые сначала | Bearer |
| `GET /api/orders/:id` | Заказ своей сессии и текущего контекста | Bearer |
| `POST /api/orders/:id/cancel` | `{}` → Order со статусом `test-cancelled` | Bearer |
| `GET /api/addresses` | Массив `{id, context, label, city, address, synthetic: true}` | Bearer |
| `GET /api/appeals` | Ранняя тестовая история текущего контекста либо `[]` | Bearer |
| `POST /api/appeals` | HTTP 503 `APPEAL_INTEGRATION_REQUIRED`, без создания записи | Bearer |
| `GET /api/returns` | Ранняя тестовая история текущего контекста либо `[]` | Bearer |
| `POST /api/returns` | `{orderId}` → HTTP 409 `ORDER_NOT_COMPLETED` для созданного/отменённого тестового заказа; иначе 503 `RETURN_INTEGRATION_REQUIRED` | Bearer |
| `DELETE /api/session` | `{deleted: true, mode: 'local-sandbox'}` | Bearer, затем токен отозван |

`Authorization: Bearer <token>` обязателен для всех пользовательских маршрутов. Сессию клиент сохраняет сам. Не пишите токен в логи, URL или общие файлы.

`ShopState`:

```ts
{
  context: 'personal' | 'organization-demo';
  carts: Record<'personal' | 'organization-demo', {productId: string; quantity: number}[]>;
  favorites: string[];
  comparison: string[]; // максимум 6; лимит расширен в V7 по master-плану
  city: string;
}
```

В каждом действии обязателен `expectedContext: 'personal'|'organization-demo'` — режим, который пользователь видел при запуске действия. Он проверяется **до любой мутации**. При рассинхронизации (например, другой вкладкой или после потерянного ответа смены режима) сервер отвечает HTTP 409 `STALE_CONTEXT` и ничего не меняет. После ошибки клиент обязан прочитать `/api/state`, обновить интерфейс и только затем разрешить новое действие; нельзя автоматически переписывать expectedContext в старом действии и повторять его. Для смены режима expectedContext означает предыдущий видимый режим, а context — новый.

Действия (поле expectedContext показано типом `ContextId`):

```ts
{type: 'context', context: 'personal' | 'organization-demo', expectedContext: ContextId}
{type: 'quantity', productId: string, quantity: number, expectedContext: ContextId}
{type: 'favorite' | 'compare', productId: string, expectedContext: ContextId}
{type: 'city', city: string, expectedContext: ContextId}
{type: 'reset', expectedContext: ContextId}
```

Сервер принимает только ID товара; цены, остатки и объект `product` от клиента запрещены. Количество: целое 0–999, 0 удаляет строку. Превышение тестового лимита — 409, без скрытого ограничения. `reset` сбрасывает корзины и предпочтения, но сохраняет историю операций.

Quote содержит `id`, `context`, `items: {productId,name,quantity,unitPriceKopecks,lineTotalKopecks}[]`, `subtotalKopecks`, `deliveryKopecks`, `totalKopecks`, `currency`, `expiresAt`, `deliveryLabel`, `mode`. Сервер берёт корзину и цены из своих данных. Срок расчёта — 10 минут. Для тестового самовывоза доставка 0; для курьера — фиксированные **49000 копеек (490 ₽), тестовый тариф**, и обязателен `addressId` из текущего контекста. Никакая отправка и бронь не происходят.

Создание Order транзакционно проверяет владельца расчёта, текущий контекст, TTL и неизменность корзины. Поля Order: `id`, `number`, `context`, `items`, `totalKopecks`, `deliveryKopecks`, `status: 'test-created'|'test-cancelled'`, `createdAt`, `cancelledAt?`, `deliveryLabel`, `currency`, `mode`. Оплаченного/возмещённого статуса нет.

`Idempotency-Key` — 8–128 латинских букв, цифр, `_` или `-`. При неопределённом результате клиент может повторить **тот же запрос с тем же ключом**: возвращается тот же заказ, второй не создаётся. Один ключ с другим quoteId — 409. Повтор уже использованного расчёта с новым ключом — 409. Создание очищает только корзину контекста расчёта. Автоматически повторять оформление с новым ключом запрещено. После успешного ответа клиент отдельно обновляет `/api/state` и историю.

Обращения собственного сайта используют `THEME` из базы Bitrix (`site-source/local/ajax/lk/appeals/appeals-questions.php:20`); отправка требует theme и comment (`appeals-text-action.php:23–30`). Для проблемы с заказом дополнительные `TAGS_HELP` тоже берутся из БД (`appeals-order-form.php:27`). Этих канонических значений в архиве нет. Свободное поле topic не является эквивалентом темы сайта. Поэтому POST отклоняется с `APPEAL_INTEGRATION_REQUIRED`; если передан orderId, до этого проверяются владелец и текущий контекст. Новых записей и внешних сообщений нет.

Возврат на сайте начинается с завершённого заказа `STATUS_ORDER_FINISH` и выбранных товаров (`site-source/local/ajax/lk/returns-products/returns-product.php:31–41`); причины `REASONS` берутся из БД (`:45`), комментарий и медиа привязаны к отдельному товару. Возврат всего только что созданного заказа с произвольной причиной нарушал бы этот процесс. POST для `test-created` и `test-cancelled` отвечает 409 `ORDER_NOT_COMPLETED`; любой иной исторический статус всё равно получает 503 `RETURN_INTEGRATION_REQUIRED` до восстановления доступных товаров, причин и обработки медиа. Клиент не может передать статус «завершён» или создать его отдельным endpoint. Поля reason/message раннего API допускаются только для корректного отказа старым клиентам и не сохраняются.

GET сохраняет доступ к ранней тестовой истории, если она уже была записана: общие поля `id`, `number`, `context`, `orderId`, `status`, `createdAt`, `mode`; для обращений также topic/message, для возвратов reason/message. Эта история не свидетельствует о принятом магазином обращении или возврате. Текст отображается текстовым компонентом, без HTML-интерпретации. На новом стенде списки пусты.

## Проверка

```sh
cd /Users/prom23/Projects/prom23-mobile/server
/Users/prom23/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node --test test/*.test.mjs
```

22 интеграционных теста запускают HTTP на случайном loopback-порту и отдельной временной SQLite-БД. Проверены: явный пустой/некорректный импорт; источники каталога; хеши токенов; изоляция пользователей и контекстов; валидация количества/полей/JSON; сравнение; серверная арифметика в копейках и адреса; одновременные повторы заказа; replay и конфликт ключа; TTL; изменение корзины; отмена; восстановление после открытия БД; Origin allowlist, включая конфигурацию; 32 КБ; точные маршруты/методы; каскадное удаление и отзыв токена. Дополнительно проверены квота сессий и освобождение места, квоты расчётов/заказов, сохранение истории при отказе, удаление только истёкших неиспользованных расчётов и реальное достижение SQLite page cap с HTTP 429 и корректным откатом транзакции. Для каждого из шести типов действий проверено отклонение отсутствующего и устаревшего expectedContext без изменения корзин/предпочтений, а затем успешное действие после обновления контекста. Проверены запрет создания обращений/возвратов, отказы 409/503 по статусу заказа, отсутствие новых записей и изоляция/сохранение/каскадное удаление ранней тестовой истории.

Это проверки локального API. Нагрузочное испытание, аудит production-инфраструктуры и реальная интеграция с магазином не выполнены этим набором.
