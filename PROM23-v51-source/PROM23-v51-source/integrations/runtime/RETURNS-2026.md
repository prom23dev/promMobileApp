# Подключение возвратов после проверки в среде магазина

Основной отчёт: ../../docs/parity/RETURNS_17.md.

Обновить согласованным комплектом ServiceDriver, ReturnWriter, WorkspaceDriver, UploadDriver и form-contracts.json. Сохраняются настройки enabledForms, enabledOperations, sourceSecretsReplaced, аутентификация, consent ledger и request ledger. Не подключать новый мобильный UI к старому обработчику: он запрещает повторную заявку на весь заказ.

ReturnWriter пишет в существующий инфоблок и JSON_RETURNS; новый ключ QUANTITY не заменяет поля старых записей. До включения проверить текущие настройки инфоблока и STATUS/REASONS, права сотрудника организации, загрузку файлов и реальные обработчики событий. Создание заявки не является согласием на возврат денег; исключить автоматическую выплату только по факту IN_WORK.

Для старого сайта отдельно дан source-patches/returns-intake-2026.patch. Применять на копии совпадающего исходника, с резервной копией, проверить git apply --check --ignore-space-change. Не переносить 14-дневный отсев в новый endpoint. Не применять потребительские сроки к B2B автоматически.

Замороженный return-rules-2026-09-14.html нужно предоставлять покупателю при передаче товара; общая публичная ссылка сама по себе не подтверждает вручение. Подставить фактические реквизиты продавца заказа в комплект передачи. После подтверждённого вручения/доставки вызвать ReturnInformationReceipt::recordProvided с уникальным ID события, ID заказа, продавцом, версией, SHA256 именно переданного файла, каналом, временем и ID доказательства. Не вызывать из page view, события создания заказа или только постановки email в очередь. Сохранять неизменяемую копию переданного файла и подтверждение вручения. Реальный источник этих событий здесь не подключён.

Проверки: PHP test/IntegrationDrivers.test.php; test/ReturnWriter.test.php; test/ReturnInformationReceipt.test.php (нужен PDO SQLite). Затем интеграционные сценарии: два разных товара в двух заявках одного старого заказа; второе требование по одному товару; чужая организация; количество больше заказа; 10 файлов в каждом из двух товаров; невалидное/длинное видео; ошибка БД после сохранения файла; повтор HTTP-запроса с тем же ключом; отзыв согласий не должен скрывать законные альтернативные способы претензии. Установить актуальную согласованную редакцию оферты и реквизиты каждого продавца.

В исходных personal/organization_returns_applications_detail/templates/.default/template.php:117 комментарий выводится без HTML-экранирования. Патч включает исправление этих двух шаблонов (всего пять файлов). После проверки установить returns.legacyTemplatesEscaped=true в приватном config. До этого новый runtime блокирует запись возврата. Текст хранится исходным, экранирование выполняется при выводе.
